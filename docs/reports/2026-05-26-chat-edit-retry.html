聊天消息编辑与重试

日期：2026-05-26 · 分支：Neo_Aspect

修改内容

  • 在聊天用户气泡上加入“编辑并重试”按钮；点击后会把原消息放回输入框，并把发送按钮切换为“重试”。
  • 重试发送时，前端会从被编辑的用户消息处截断当前可见分支，再插入编辑后的新消息。
  • 历史消息恢复时保留 assistant_turn，让前端知道该从哪一轮截断持久化历史。
  • 后端 TopicStore 新增从指定 assistant turn 起截断话题历史的能力，并重写 full.jsonl 与 summary.json 尾部。
  • /api/chat/stream 支持 retry_from_assistant_turn，重试时先截断旧分支，再追加新的问答。
  • 补充前端静态契约、TopicStore 历史截断、聊天流重试持久化三组回归测试。

达成效果

  • 用户可以像 Codex 一样编辑已发送消息并重新发送。
  • 旧回答和旧分支会从界面上消失，避免同一个话题里出现两条互相冲突的后续路径。
  • 持久化话题会同步替换旧分支，刷新历史后不会把被编辑掉的内容又带回来。
  • 本地浏览器检查覆盖了输入、点击编辑、改写、重试发送和界面截断流程。

验证记录

  • python -m unittest tests.test_chat_modes_ui tests.test_chat_topics tests.test_neo_backend_contract -v：40 项通过。
  • python -m py_compile backend/app.py backend/chat_topics.py：通过。
  • 浏览器预览：点击“编辑并重试”后输入框恢复原文，重试发送后旧用户消息及其后续系统错误被截断。

待办事项

  • 后续可把编辑重试状态做成更明确的小提示，例如输入框上方显示“正在重试第 N 轮”。
  • 等 Brain 使用完整历史上下文时，可增加一条端到端测试确认旧分支不会进入模型上下文。
  • 如果未来恢复长期摘要压缩，需要决定截断旧分支后是否保留截断点之前的 summary block，而不是统一回退为 raw block。

推荐下一步

  • 继续做聊天体验的“小闭环”：停止生成、重新生成最后一次回复、复制消息。
  • 或者进入 Memory Review 队列，把“任务完成后主动总结并建议保存”的 review 流程落到 UI。
