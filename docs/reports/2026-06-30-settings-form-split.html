Settings Form Split

Goal

拆出 settings.js 中的表单模型读写、默认值合并、静态 fallback、点击预览和 provider 表单同步逻辑，放入新的普通浏览器脚本 settings_form.js，同时保留兼容 wrapper。

Worker / Subagent Split

本轮由子窗口 worker 在共享工作区直接实现；主窗口只负责后续验收。未执行 stage、commit、cleanup 或 revert。

Files Changed

  • settings_form.js: 新增 window.IpetSettingsForm.createSettingsFormController，承接表单默认值和读写主体逻辑。
  • settings.js: 表单相关同名函数改为委托 formController 的薄 wrapper，保留加载、保存、导航和 model picker 接入。
  • settings.html: 在 settings_model_picker.js 和 settings.js 前加载 settings_form.js。
  • backend/app.py: 增加 SETTINGS_FORM_JS_PATH 和 /settings_form.js 静态路由，沿用 no-store 资源响应。
  • tests/test_settings_form_source.py: 新增源码契约测试，覆盖加载顺序、namespace、薄 wrapper、主体逻辑迁移和静态路由。
  • tests/test_neo_aspect_settings_page.py: 调整现有设置页源码断言到新的模块边界。

Achieved Effect

settings.js 不再内联 clone、默认值、fallback、populate/readForm 主体；model picker 仍通过 settings.js 的 readForm、renderSummary、stringValue 和 isGoogleAistudio 兼容入口工作。

Remaining Work

本轮未拆 settings.js 的页面导航、保存加载、summary/diagnostics 渲染逻辑；这些可作为后续更小拆分继续处理。

Recommended Next Step

下一轮可拆出 settings summary/diagnostics 渲染，或把 settings 页事件绑定整理成独立 controller，但应继续保留薄 wrapper 和无 bundler 入口。
