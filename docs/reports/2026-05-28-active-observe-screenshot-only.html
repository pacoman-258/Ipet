Active Observe 回归到截图优先

本轮回应“观察逻辑不是通过截图吗”的问题：active observe 不再额外依赖 macOS 前台应用元数据脚本，截图成功就是观察成功，元数据超时不会再污染用户可见结果。

Goal

  • 解释元数据原本用途：辅助识别前台 App、窗口标题和菜单栏，但它不是 Human Ops 观察的必要路径。
  • 移除 active observe 中阻塞式 AppleScript 元数据读取，降低系统复杂度。
  • 当截图已经成功但没有 OCR/VLM 观察结果时，给出准确表述：已截取屏幕，但还未提取明确内容。

Worker Split

  • Debugger: 追踪截图中显示的 osascript timed out 来源，确认它来自辅助元数据读取，不是截屏失败。
  • Backend: 过滤旧元数据超时噪声，并在有截图数据时返回截图成功的观察文本。
  • Body: 从 active observe 截图路径移除前台 App 元数据读取。
  • QA: 添加回归测试，确认元数据超时不会再作为观察失败展示。

Files Changed

  • main.py: active observe 捕获截图后不再调用 collect_screen_observations 读取 macOS 前台应用元数据。
  • backend/app.py: _observation_text_from_result 过滤元数据超时噪声；有截图时返回“已截取当前屏幕”。
  • tests/test_neo_backend_contract.py: 新增回归测试覆盖 osascript 元数据超时不污染 observe 文案。

Achieved Effect

  • Human Ops active observe 的主路径更清晰：截图 -> 可选 VLM/OCR -> 观察文本或点击目标。
  • macOS 元数据脚本不再参与 active observe，因此它的超时不会阻断或盖过截图结果。
  • 如果没有配置/没有成功提取视觉内容，Ipet 会诚实说明已经截屏但未提取明确内容。
