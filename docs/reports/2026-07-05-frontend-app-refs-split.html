Frontend App Refs Split

Goal

Move the top-level DOM reference collection out of frontend/index.js into a focused frontend module while preserving existing controller ref injection semantics.

Worker / Subagent Split

frontend/body subwindow implemented the split directly in the current worktree. Main window remains responsible for review and cross-worker coordination.

Files Changed

  • frontend/app_refs.js: new window.IpetAppRefs.collectAppRefs(document) module.
  • frontend/index.js: replaced inline DOM queries with app refs collection and same-name destructuring.
  • index.html: loads frontend/app_refs.js after app state and before controllers/app.
  • tests/test_frontend_app_refs_source.py: new source and Node/vm tests for the ref collector.
  • tests/test_chat_modes_ui.py: updated source assertions so chat mode button collection is owned by app refs.
  • docs/reports/2026-07-05-frontend-app-refs-split.html: this report.

Achieved Effect

frontend/index.js no longer calls document.getElementById or document.querySelectorAll directly. All previous DOM refs, including chat and memory mode button arrays, are collected in frontend/app_refs.js and passed onward with the original variable names.

Remaining Work

No known remaining work for this split. Broader frontend module extraction can continue in later worker rounds.

Have the main window review the scoped diff, then continue with the next narrow frontend/index.js responsibility extraction.
