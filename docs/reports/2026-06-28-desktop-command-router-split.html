Desktop Command Router Split

GREEN 2026-06-28 desktop-shell worker report

Goal

Move the desktop command routing logic out of main.py into app.desktop_command_router.DesktopCommandRouter while keeping DesktopPet compatibility wrappers and existing command behavior stable.

Worker Split

  • Lead worker: desktop-shell.
  • Scope kept to the desktop host command bridge and its focused regression tests.
  • No backend, frontend, Body, Human Ops, settings, staging, commit, cleanup, or revert work was performed.

Files Changed

  • main.py: imports and constructs DesktopCommandRouter, then keeps command methods as thin compatibility wrappers.
  • app/desktop_command_router.py: new pure Python router for mtime polling, heartbeat writing, response writing, and desktop command execution.
  • docs/reports/2026-06-28-desktop-command-router-split.html: this report.

Achieved Effect

  • DesktopPet._desktop_command_mtime_token, _write_desktop_host_heartbeat, _response_path_for_command, _write_desktop_command_response, on_desktop_command_poll, and process_desktop_command now delegate to the router.
  • The router preserves command semantics for model loading, motion and expression playback, file pickers, Human Ops click/text/key actions, and active vision capture.
  • The response shape remains nonce, type, status, ok, result, and timestamp_ns.
  • The router does not import main; Qt, Human Ops, path, clock, and active vision dependencies are injected by main.py.
  • Legacy tests that call main.DesktopPet.process_desktop_command(host, command) with a fake host remain supported through lazy router construction.
