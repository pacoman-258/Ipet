Brain Hidden Dock Screen Edge Affordance

Date: 2026-06-08

Goal

Improve Brain so a complex desktop task can progress through simple human actions: observe, click, type text, and press Enter. This round focused on the live blocker where macOS Dock was hidden, the visual observer timed out, or the observer saw the WeChat Dock icon without returning coordinates, leaving Brain with no reviewable click target after repeated observes.

Worker Or Subagent Split

  • Brain owner: added prompt guidance for a one-time hidden-Dock reveal step.
  • Body/backend owner: derived a screen-edge affordance from negative Dock visibility and screen bounds.
  • QA owner: added targeted contract tests and ran full unittest regression.

Achieved Effect

When observation says Dock or the WeChat icon is not visible, Brain still cannot fabricate a Dock app icon. If the VLM times out but the screenshot was captured, Brain also does not get a fake icon. Instead, when screen bounds are available, the backend provides a concrete bottom-edge click affordance. Brain can turn that into a Human Ops approval request with coordinates and continue_after_approval=true, then observe again before searching for the actual WeChat icon.

A second live blocker was also handled: when Brain already knows the Dock icon is visible but still lacks its center coordinates, a generic Observe screen no longer asks the VLM to describe the whole screen. The backend uses Brain's goal state to ask only for the target center x/y, and marks observe_coordinate_incomplete if that still fails.

Follow-up observes now keep the original objective as the active target hint when Brain says screen, so VLM timeouts and fallback extraction still know the task is about WeChat. Coordinate-incomplete observations also no longer short-circuit the ReAct loop when they already contain a concrete reviewable click affordance.

Body now reads visible Dock item names and positions from macOS accessibility as observation candidates. When the VLM says the WeChat Dock icon is visible but omits coordinates, the structured context can still provide the Dock icon center point for Human Ops review. When both sources exist, the Dock accessibility center point is preferred for Dock app icons because it comes from the actual visible Dock UI.

Human Ops also now allows a longer active vision capture window so macOS window discovery, Dock item discovery, and screenshot capture do not time out before the separate VLM call.
