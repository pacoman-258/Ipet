Playwright 真实 Chrome 个人资料修复

目标

修复“用户选择了 Chrome 个人资料，但 Playwright 实际创建空白资料”的问题，并在证据足够时复用已经打开的所选 Chrome 窗口。

Worker / subagent 分工

主代理单独完成 Human Ops 执行器、Brain 合同、测试、文档与报告；本轮未启用 subagent。

修改文件

  • human_ops/chrome_profiles.py：解析 Chrome Local State、精确匹配资料、创建私有登录态快照、检查唯一活跃资料与 CDP。
  • human_ops/playwright_actions.py：将 open/attach 接到真实资料解析、窗口复用和显式失败语义。
  • backend/app_action_adapters.py、backend/react_prompts.py、brain/llm.py：更新审批披露和模型能力合同。
  • tests/test_playwright_actions.py 及相关合同测试：覆盖资料匹配、登录态复制、原资料不变、未知资料、唯一窗口复用和多资料歧义。
  • docs/WORKFLOW.md、docs/architecture.md、.gitignore：记录并隔离新的私有快照行为。

实现效果

  • 资料显示名或 Profile N 目录名必须精确命中 Chrome 资料；不存在时返回可选名称，不再创建同名空资料。
  • open 在所选资料是唯一活跃资料且远程调试可用时复用原窗口；否则只读复制 cookies 和网页存储到 Ipet 私有持久快照。
  • 原 Chrome 资料目录不交给 Playwright 直接启动，也不会被快照初始化写回。
  • attach 对未激活、多资料同时活跃和未开启远程调试分别显式失败。
  • 审批通知会披露认证状态复制、持久保存、窗口复用、网络与首次 CLI 获取影响。

剩余工作

自动化测试只使用临时伪造资料，没有复制用户的真实 Chrome 数据，也没有启动真实浏览器。一次真实端到端烟雾测试会读取并复制所选资料的认证状态、启动 Chrome 并访问网络，因此必须在用户明确批准后执行。

验证

  • Playwright、Brain、Human Ops 定向回归：53 项通过。
  • 全量回归：750 项通过。
  • 相关 Python 文件编译检查通过；git diff --check 通过。

建议下一步

重启 Ipet 后，用 Chrome 中显示的精确资料名批准一次 Playwright open。若坚持复用现有窗口，请先在该资料打开 chrome://inspect/#remote-debugging 并启用远程调试，同时只保留该资料为活跃资料。
