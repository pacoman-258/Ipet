Backend Settings Routes Split

Status: DONE

Goal

Move the settings page assets and /api/settings/config FastAPI route shells out of backend/app.py into a dedicated settings route module while preserving paths, methods, response shapes, and status codes.

Worker / Subagent Split

Backend subwindow owned the implementation and tests. The main window is expected to review only. No frontend, desktop host, or unrelated backend worker files were intentionally changed.

Files Changed

  • backend/app.py: imports and registers the split settings router through explicit dependencies.
  • backend/settings_routes.py: owns settings asset and config API route handlers.
  • tests/test_backend_settings_routes.py: covers delegated route behavior and app source split constraints.
  • tests/test_settings_form_source.py: now checks form asset routing through backend/settings_routes.py and app dependency injection.
  • tests/test_settings_model_picker_source.py: now checks model picker asset routing through backend/settings_routes.py and app dependency injection.
  • docs/reports/2026-07-05-backend-settings-routes-split.html: records this task round.

Achieved Effect

  • backend/app.py no longer defines inline settings route decorators.
  • The new route module exposes SettingsRouteDependencies, create_settings_router, and register_settings_routes.
  • Compatibility helpers such as _settings_payload and _apply_settings_update remain in backend/app.py.
  • Dependency wrappers preserve existing monkeypatch behavior for settings config tests.
  • Legacy source tests for settings_form.js and settings_model_picker.js now assert the split route location instead of app-level decorators.

Remaining Work

None for this split. The main-window validation failures from stale source tests were aligned with the split route architecture without changing production code.
