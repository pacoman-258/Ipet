真实 Observe 与点击链路测试

目标

对 Ipet 的真实屏幕观察、观察后点击 App、以及底层点击执行链路做分层测试，定位链路上实际失败的位置。

Worker / Subagent Split

本轮由 Codex 直接执行，按 Neo Aspect ownership 归入 body、brain、human-ops 和 qa-reports 的交叉验证；未启用独立子代理。

测试步骤与结果

步骤 结果 定位结论
启动 Ipet 桌面主机 成功，Qt 输出 QWebChannel ready，心跳 PID 更新。 桌面主机可运行；旧心跳曾是 stale，未启动前命令无人消费。
直接发送 active_vision_capture 桌面命令 成功，macos_screencapture 捕获 1920x1249 截图，active_observation.status=success。 命令文件、Qt 轮询、截图、响应文件链路可用。
窗口与 App 目标发现 desktop_targets_count=0；System Events 返回 -10827；AppKit 兜底不可用，报 No module named 'AppKit'。 自动目标枚举失败，Ipet 无法从本地元数据拿到窗口坐标或可靠 App 候选。
完整聊天 observe 请求 成功进入 human_ops_observe，Google observe 模型返回截图理解，Brain 汇总回复。 Brain -> Human Ops observe -> 截图 -> observe 模型 -> Brain 汇总链路可用。
完整聊天“观察并点击微信 App”请求 observe 模型识别到 Dock 微信图标，但只返回残缺坐标 x=；随后 Brain follow-up 返回 OpenAI-compatible provider returned empty text。 自然语言坐标抽取/模型输出稳健性不足，未生成 propose_act，所以 Human Ops 审批和点击没有进入。
手动提供微信 running-app 候选后执行 focus_target 成功，action_trace 为 activate_running_app，focus_result.status=success。 轻交互激活分支可用；主要问题在自动候选发现。
直接发送 human_ops_click 到屏幕中心 成功，返回 method=core_graphics。 底层鼠标事件执行器可用；点击失败不是 CoreGraphics 发不出去。

Achieved Effect

已把 observe/click 链路拆成可验证层级，并确认截图、observe 模型、轻交互激活、底层 CoreGraphics 点击均能工作。

Remaining Work

  • 修复 macOS 目标发现：System Events -10827 权限/脚本失败，以及当前环境缺少 AppKit 兜底。
  • 增强 observe 坐标输出约束：模型返回残缺坐标时，应触发再次 observe 或明确失败，而不是把残缺文本交给 Brain 碰运气。
  • 增强 Brain follow-up 容错：外部 provider 返回 empty text 时，应保留 observation 事实并要求补充坐标，而不是直接结束点击链路。

Recommended Next Step

优先修复目标发现和坐标恢复路径：让 Ipet 在无法枚举窗口时，能基于截图进行第二次坐标询问，并且在 observe 未返回完整 x/y 时禁止生成点击 proposal。
