Frontend Human Ops Preview Split

Goal

Move the Human Ops click preview DOM and Qt bridge logic out of frontend/index.js into a dedicated preview controller while keeping the legacy app-level function names as thin wrappers.

Worker/Subagent Split

Single frontend worker. No subagents were used. The work stayed inside the requested frontend, test, and report files while parallel backend and desktop edits were left untouched.

Files Changed

  • frontend/human_ops_preview.js - new controller module.
  • frontend/index.js - delegated preview wrappers to the controller.
  • index.html - loaded the new module before frontend/index.js.
  • tests/test_frontend_human_ops_preview_source.py - new source tests for the split.
  • tests/test_chat_modes_ui.py - minimal source-test alignment for the new module.
  • docs/reports/2026-07-03-frontend-human-ops-preview-split.html - this report.

Achieved Effect

  • Added window.IpetHumanOpsPreview.createHumanOpsPreviewController(...) with private preview element state.
  • Injected getQtBridge, window, and document so the new module does not depend on the global qtBridge.
  • Kept showHumanOpsClickPreview(preview) and hideHumanOpsClickPreview() in frontend/index.js as one-line wrappers.
  • Preserved red-dot validation, viewport bounds checks, DOM marker creation, and Qt showClickPreview/hideClickPreview calls in the new module.

Remaining Work

None for this split. Broader frontend extraction can continue in later waves.

Recommended Next Step

Continue the next frontend split by targeting another small ownership island in frontend/index.js, keeping the same controller plus source-test pattern.
