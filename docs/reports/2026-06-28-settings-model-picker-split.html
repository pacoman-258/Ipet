Settings Model Picker Split

GREEN Worker report for the settings-console model picker split.

Goal

Move Brain and Observe model fetch/render behavior out of settings.js into a focused settings model picker module while preserving the settings UI, button behavior, and /api/brain/models request payloads.

Worker / Subagent Split

This split implementation worker acted as settings-console lead and qa-reports reporter. No separate subagent was used. Existing dirty worktree changes were treated as owned by other workers and were not reverted, staged, cleaned, or committed.

Files Changed

  • settings_model_picker.js: added window.IpetSettingsModelPicker.createSettingsModelPickerController(deps) and moved Brain/Observe model option rendering and fetch logic.
  • settings.js: created the model picker controller with injected helpers and retained thin compatibility wrappers.
  • settings.html: loads /settings_model_picker.js before /settings.js.
  • backend/app.py: serves /settings_model_picker.js with the same no-store settings asset response pattern.
  • tests/test_settings_model_picker_source.py: added focused source coverage for namespace, split boundary, payload semantics, loading order, and backend route.
  • tests/test_neo_aspect_settings_page.py and tests/test_chat_modes_ui.py: updated source assertions to verify the new split location.
  • docs/reports/2026-06-28-settings-model-picker-split.html: recorded this task round.

Achieved Effect

  • Brain and Observe model status updates, model button rendering, and model list fetches now live in settings_model_picker.js.
  • settings.js keeps the original function names and event binding surface but delegates to modelPickerController.
  • The model fetch payload keeps provider, model_endpoint, optional api_key, and Observe scope: "observe".
  • Google AI Studio still allows hostless model fetching because the endpoint guard remains !endpoint && !isGoogleAistudio(provider).

Remaining Work

No remaining implementation work for this split. Manual browser or desktop settings smoke testing was not run in this worker round.
