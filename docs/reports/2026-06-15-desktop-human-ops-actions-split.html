Desktop Human Ops Actions Split

Date: 2026-06-15

Goal

Move macOS Human Ops desktop execution actions out of main.py into human_ops/desktop_actions.py, while keeping the same main.py wrapper names available for existing imports and tests.

Worker Split

This round was handled by the desktop Human Ops actions split worker. The main window remains responsible for review and integration checks.

Files Changed

  • human_ops/desktop_actions.py: new module for click, type text, Enter/Return key press, CoreGraphics fallback, AppleScript escaping, and Qt event helper behavior.
  • main.py: replaced inline Human Ops action implementations with wrappers that delegate to the new module and inject QApplication for Qt event processing.
  • tests/test_desktop_actions.py: focused coverage for the new module, macOS-only errors, payload fields, CoreGraphics-to-System Events fallback, Enter key code 36, no main.py import, and injected Qt event handling.
  • docs/reports/2026-06-15-desktop-human-ops-actions-split.html: this task report.

Achieved Effect

  • Human Ops desktop execution code is now owned by human_ops/desktop_actions.py.
  • main.py still exports _screen_coordinate, _CGPoint, _post_core_graphics_click, execute_human_ops_click, _applescript_string, execute_human_ops_type_text, execute_human_ops_key_press, _process_pending_qt_events, _hide_window_for_desktop_click, and _restore_window_after_desktop_click.
  • The new module has no import dependency on main.py.
  • The macOS-only error text, click result payloads, type text payloads, key press payloads, CoreGraphics preference, System Events fallback, and Enter/Return key code 36 behavior are preserved.
