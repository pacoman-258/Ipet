Backend Final Routes Split

Completed 2026-07-07

Goal

Move the final app-level FastAPI route decorators out of backend/app.py while preserving the existing health, chat stream, and Human Ops approval behavior.

Worker / Subagent Split

Backend split worker handled the route extraction and verification in this task window. Main-window responsibility remains review only. No staging or commits were performed.

Files Changed

  • backend/app.py: replaced the remaining route decorators with dependency builders and route registration calls.
  • backend/health_routes.py: added the /api/health router, payload helper, and registration API.
  • backend/chat_stream_routes.py: added the /api/chat/stream router around stream_chat_response.
  • backend/human_ops_decision_routes.py: added the Human Ops decision router around stream_human_ops_proposal_decision.
  • tests/test_backend_route_split.py: added coverage for final route decorators, route module interfaces, delegation, 404 conversion, and per-request dependency resolution.
  • docs/reports/2026-07-07-backend-final-routes-split.html: this report.

Achieved Effect

  • backend/app.py no longer declares @app.get, @app.post, @app.websocket, or @app.delete routes.
  • The health payload keeps the same service fields, Neo Aspect flags, ASR/TTS flags, message, and app.version value.
  • Chat streaming still delegates to stream_chat_response with ChatStreamFlowDependencies and returns text/event-stream.
  • Human Ops decisions still delegate to stream_human_ops_proposal_decision with HumanOpsApprovalFlowDependencies, return text/event-stream, and convert HumanOpsProposalNotFound to HTTP 404.
  • Route dependencies are resolved per request so existing tests and runtime monkeypatching see current app-level functions, matching the old decorator implementation.
