Desktop Qt Bindings Split

Goal

Move the PyQt6/PySide6 conditional import block out of main.py while keeping Qt runtime setup, binding priority, and module-level Qt symbol exports compatible.

Worker Or Subagent Split

desktop-shell implemented the split in the current workspace. No backend, frontend, settings, or other worker report files were modified.

Files Changed

  • main.py: imports load_qt_bindings, calls it after _apply_qt_runtime_env(), and re-exports the previous Qt names at module scope.
  • app/qt_bindings.py: new loader module with QtBindings and PyQt6/PySide6 fallback order.
  • tests/test_desktop_qt_bindings.py: new unit and source-shape tests for binding order, aliases, and main.py compatibility.
  • docs/reports/2026-07-05-desktop-qt-bindings-split.html: this report.

Achieved Effect

  • main.py no longer contains direct from PyQt6... or from PySide6... import blocks.
  • macOS still prefers PyQt6 with PySide6 fallback; non-macOS still prefers PySide6 with PyQt6 fallback.
  • Existing callers can still access names such as main.Qt, main.QApplication, and main.QWebEngineView.
  • The Qt runtime environment remains applied before Qt binding import.

Remaining Work

No remaining work for the requested main.py binding split. A future desktop-shell task could separately review other Qt-loading modules such as app/control_panel.py, which was intentionally out of scope here.

Recommended Next Step

Have the main window review only the changed files and then continue with the next planned main.py responsibility split.
