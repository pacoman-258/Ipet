Desktop Context Menu Split

Goal

Move DesktopPet.show_context_menu menu construction and selected-action dispatch from main.py into app/context_menu.py, leaving the desktop host method as a thin delegate.

Worker / Subagent Split

This round was handled by the desktop-shell worker. The coordinator/main window is expected to inspect only; no staging, commit, dependency install, network call, destructive cleanup, or cross-worker revert was performed.

Files Changed

  • main.py: imports and constructs DesktopContextMenuController, stores it on DesktopPet, and delegates show_context_menu.
  • app/context_menu.py: new controller that builds the right-click menu, executes it at owner.browser.mapToGlobal(pos), and dispatches selected actions.
  • tests/test_desktop_context_menu.py: new focused tests for controller behavior, module isolation from main, and the thin DesktopPet delegate.
  • docs/reports/2026-07-03-desktop-context-menu-split.html: this task report.

Achieved Effect

The context menu behavior remains unchanged: settings opens the settings page, lock toggles owner.window_locked and owner.config["window"]["locked"], reload reapplies web config, and quit closes the owner. The Qt menu classes remain injected from main.py, while menu behavior is no longer inline in DesktopPet.

Remaining Work

No known remaining implementation work for this split. Existing unrelated dirty files were left untouched.

Recommended Next Step

Have the main coordinator review the focused diff and, if desired, run a broader desktop-shell regression after other parallel workers finish their slices.
