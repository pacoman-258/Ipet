Desktop Pet Bridge Split

Goal

Move the PetBridge signal and slot class body out of main.py while preserving main.PetBridge and the existing Qt bridge behavior.

Worker / Subagent Split

This worker implemented the desktop bridge split directly in the shared worktree. The main window remains responsible for review and acceptance.

Files Changed

  • app/pet_bridge.py: new Qt-neutral factory create_pet_bridge_class with injected QObject base, signal factory, slot decorator, and print function.
  • main.py: imports the factory and keeps the public PetBridge name by creating it from the active Qt binding.
  • tests/test_desktop_pet_bridge.py: fake QObject, Signal, and Slot tests for bridge emissions and logging without starting real Qt.
  • docs/reports/2026-07-01-desktop-pet-bridge-split.html: this report.

Achieved Effect

main.py no longer contains the full PetBridge class definition. The bridge behavior remains unchanged for DesktopPet.__init__: state, settings, ASR warmup, window control, and click preview signals are still exposed on PetBridge.

Remaining Work

No known follow-up for this split. The repository was already dirty before this worker started, so unrelated files were left untouched.

Recommended Next Step

Have the main window inspect the small factory boundary and confirm later desktop splits keep Qt-specific dependencies in main.py or narrow adapter modules.
