Backend App Settings Adapters Split

Status: DONE

Goal

Move the backend settings config compatibility wrapper logic out of backend/app.py into a dedicated adapter module while keeping the legacy private names in backend.app callable and patchable for existing tests and routes.

Worker / Subagent Split

  • Implementation worker: this backend settings config wrapper split window.
  • Main window: reserved for acceptance only; it does not need to patch code.
  • Other agents: unrelated working-tree changes were left untouched.

Files Changed

  • backend/app_settings_adapters.py - new adapter module with dependency dataclass and thin delegates to backend.settings_config.
  • backend/app.py - settings config wrappers now route through the adapter module and preserve the old private names.
  • tests/test_backend_app_settings_adapters.py - new regression coverage for adapter delegation, wrapper thinness, and import boundaries.
  • docs/reports/2026-07-08-backend-app-settings-adapters-split.html - this report.

Achieved Effect

  • backend/app.py no longer contains the settings config helper bodies; it now keeps only the legacy wrapper names.
  • The new adapter module owns the dependency bundle for config_path, defaults, and allowed_keys.
  • Existing route wiring still goes through backend.app wrapper functions, so patch points remain stable.
  • Direct adapter tests confirm the helper still forwards to backend.settings_config with the expected dependencies.

Remaining Work

  • No known functional gaps from this split.
  • Future rounds can keep trimming backend/app.py only if they preserve the same wrapper contract.

Recommended Next Step

Let the main window verify the wrapper boundary, then continue with the next small extraction only if another config-related cluster is still worth splitting.
