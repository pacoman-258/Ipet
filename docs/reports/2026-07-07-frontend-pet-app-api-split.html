Frontend Pet App API Split

Goal

Move the window.PET_APP runtime API assembly out of frontend/app_bootstrap.js while preserving the existing startup behavior.

Worker / Subagent Split

Frontend split worker only. No subagent handoff. Main window role remains review-only per task direction.

Files Changed

  • frontend/pet_app_api.js: new module exposing createPetAppApi and installPetAppApi.
  • frontend/app_bootstrap.js: thin installPetAppApi() wrapper now delegates to the new module.
  • index.html: loads frontend/pet_app_api.js before frontend/app_bootstrap.js.
  • tests/test_frontend_app_bootstrap_source.py: source tests updated for the new module boundary and script order.
  • docs/reports/2026-07-07-frontend-pet-app-api-split.html: this report.

Achieved Effect

app_bootstrap now owns startup flow and dependency collection only; the PET_APP method bodies live in pet_app_api.js. Startup still calls installPetAppApi() before init(). Review follow-up now preserves injected runtime window lookup for IpetPetAppApi, and playExpression tolerates a missing petSceneController.getCurrentModel.

Remaining Work

None for this split. Other unrelated worktree changes were left untouched.

Recommended Next Step

Continue the frontend decomposition by moving the next self-contained runtime API or bridge surface behind a similarly small installer module.
