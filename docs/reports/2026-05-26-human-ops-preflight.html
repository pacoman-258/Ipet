Human Ops 开工前检查

日期：2026-05-26 · 分支：Neo_Aspect · 本轮只读检查，业务代码未修改

当前已有基础

  • human_ops/approvals.py 已有最小 ReviewableProposal，支持 act proposal 和 approval 标记。
  • human_ops/previews.py 已有点击红点预览模型，和用户先前要求一致。
  • brain/decisions.py 已区分 say、observe、propose_act、propose_remember、propose_learn_skill、stop。
  • 设置页已有 Human Ops 配置：观察屏幕、Accessibility、act/remember/learn_skill review、剪贴板写入 review、点击红点预览。
  • 文档已经把 Human Ops 定义为审批、拒绝、执行记录和风险解释层。

开工前必须钉住

  • 先定义 Neo Human Ops 的 API/SSE 契约。当前 index.html 仍有旧 approval UI，但 Neo 后端已将 /api/chat/approval 作为移除接口返回。
  • 先决定第一期 action 范围。建议只做 click、type_text、hotkey、open_app、wait，把文件/终端/网络执行排到后面。
  • 先决定审批对象格式：id、decision、risk、summary、preview、payload、created_at、status、human_note、constraints、result。
  • 先决定执行边界归属：Human Ops 只审批和记录，Body 执行已批准动作；Brain 只提出下一步。
  • 先决定点击预览坐标体系：桌面全局坐标、窗口局部坐标、截图坐标不能混用；红点必须能对应实际点击点。
  • 先决定持久化策略：pending proposal、approved/rejected 记录、execution ledger 应存在哪里，以及是否进入 Git 忽略的本地数据目录。

推荐第一期切片

  • Phase 1：只做 proposal/review 闭环，不真实点击。Brain 产生 propose_act 后，聊天里显示审批卡片和红点预览；批准/拒绝后返回 Brain 可读结果。
  • Phase 2：接入 Body 执行 click，只允许批准后的单次点击；执行后 observe 反馈。
  • Phase 3：加入 type_text、hotkey、open_app、wait，每种 action 都有独立 preview 和审计记录。
  • Phase 4：remember / learn_skill 的 review 队列与 Memory & Skills 落地。

建议补充的测试入口

  • tests/test_human_ops_api.py：proposal 创建、批准、拒绝、约束、状态转换。
  • tests/test_human_ops_execution.py：未批准不得执行，批准后只执行 payload 中的一次动作。
  • tests/test_chat_modes_ui.py：审批卡片、红点预览、拒绝输入框恢复。
  • tests/test_neo_backend_contract.py：Brain 非 say 决策不会被当作普通文本直接执行。
