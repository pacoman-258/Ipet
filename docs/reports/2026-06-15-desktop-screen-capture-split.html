Desktop Screen Capture Split

Status: implemented and under verification

Goal

Move screen capture, encoded frame payload, visual hash, display layout, and UI metadata observation helpers out of main.py into body/screen_capture.py, while keeping main.py exports as compatibility wrappers.

Worker Split

This round acted as the desktop-shell / Body screen capture split worker. The main window and startup path were kept to inspection and wrapper compatibility only. Active Vision candidate discovery and Human Ops click/type/key execution remained in main.py.

Files Changed

  • body/screen_capture.py: new Body module for capture payload composition, Qt screenshot encoding, macOS screencapture payloads, text cleanup, and screen observation metadata.
  • main.py: replaced the moved implementation with thin wrappers that pass the already-selected Qt binding classes into the Body module.
  • tests/test_screen_capture_payload.py: new focused unittest coverage for pure payload logic and injected capture paths.
  • docs/reports/2026-06-15-desktop-screen-capture-split.html: this report.

Achieved Effect

  • body.screen_capture can be imported without importing PySide6 or PyQt6 at module import time.
  • main.py still exports the previous screen capture function names for existing imports and monkeypatch-oriented tests.
  • Capture payload fields such as capture_scope, capture_backend, display_layout, display_count, frame_hash, visual_hash, and encoded image dimensions are preserved.
  • Qt dependency selection remains owned by main.py during desktop startup; the new module uses dependency injection or lazy fallback only when called directly.

Verification

  • RED: python -m unittest tests.test_screen_capture_payload -v failed with four assertions because body.screen_capture was not importable.
  • GREEN smoke: python -m unittest tests.test_screen_capture_payload -v passed after adding the module.
  • Compatibility smoke: python -m unittest tests.test_desktop_runtime tests.test_main_runtime_env -v passed before final report-time verification.

Remaining Work

No intentional behavior change remains in this split. Broader Active Vision candidate discovery and Human Ops execution helpers are still in main.py by design for this round.

Recommended Next Step

Continue with a separate owner-scoped split for Active Vision discovery or Human Ops execution only after this capture payload boundary is reviewed.
