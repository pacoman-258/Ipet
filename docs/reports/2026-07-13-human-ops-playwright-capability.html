Human Ops Playwright 能力

日期：2026-07-13

目标

让 Human Ops 能审批并执行受限 Playwright 浏览器动作；告诉 Brain 对浏览器页面任务优先考虑 Playwright，同时保留用户明确要求或 Playwright 无法覆盖时的原生/虚拟操作降级路径。

Worker / subagent split

本轮由主 agent 单独完成；未使用 subagent。

Files changed

  • human_ops/playwright_actions.py：安全参数合同、CLI 定位、隔离会话与异步执行。
  • human_ops/approvals.py、human_ops/proposals.py、human_ops/approval_flow.py、human_ops/approval_prompts.py：审批、展示和结构化验证。
  • backend/app_action_adapters.py、backend/react_prompts.py：执行适配与 ReAct 动作校验。
  • brain/llm.py：浏览器优先、用户覆盖和能力不足降级提示。
  • docs/WORKFLOW.md、docs/architecture.md：行为与安全边界。
  • tests/test_playwright_actions.py 及相关 Human Ops / Brain / backend 回归测试。

Achieved effect

Playwright 现在是一类独立的 Human Ops 审批动作。允许的操作限于 HTTP(S) 打开页面、快照、基于 e<number> ref 的点击/填充、文字/按键、导航和标签页；任意 JavaScript、raw CLI、文件 URL 和猜测选择器都会失败关闭。执行结果把页面输出交回 Brain，不会为了验证默认切换 macOS 焦点或截图。

审批通知会说明首次运行可能由 npx 获取 @playwright/cli，以及目标页面可能触发网络访问。
