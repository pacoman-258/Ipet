Desktop Action Bridge Split Report

Goal

Move the Human Ops desktop action and Qt QApplication dependency wrapping out of main.py into app/desktop_action_bridge.py, while preserving the public compatibility functions that tests and DesktopCommandRouter patch.

Worker / Subagent Split

Desktop worker implemented the file changes. The main window remains responsible for review only. No other worker-owned files were reverted, reformatted, staged, committed, or cleaned.

Files Changed

  • main.py: imports create_desktop_action_bridge and delegates the existing Human Ops compatibility wrappers through a bridge factory bound to QApplication.
  • app/desktop_action_bridge.py: new dataclass bridge around human_ops.desktop_actions and injected qapplication.
  • tests/test_desktop_action_bridge.py: new focused tests for import isolation, action delegation, real action behavior through the bridge, and injected QApplication event handling.
  • docs/reports/2026-07-03-desktop-action-bridge-split.html: this report.

Achieved Effect

main.py no longer imports human_ops.desktop_actions directly. It keeps _screen_coordinate, _CGPoint, _post_core_graphics_click, execute_human_ops_click, execute_human_ops_type_text, execute_human_ops_key_press, _process_pending_qt_events, _hide_window_for_desktop_click, and _restore_window_after_desktop_click as thin compatibility wrappers. DesktopCommandRouter injection still receives the same patchable names.

Remaining Work

No remaining work for this split. The underlying human_ops/desktop_actions.py behavior was intentionally left unchanged.

Recommended Next Step

Have the main window review the bridge boundary and continue with the next planned desktop split if the compatibility surface looks acceptable.
