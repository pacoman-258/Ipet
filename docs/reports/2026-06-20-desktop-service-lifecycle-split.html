Desktop Service Lifecycle Split

GREEN 2026-06-20 desktop-shell worker report

Goal

Move backend, ASR service, ASR warmup monitor, and managed-process shutdown lifecycle logic out of main.py into an app-layer lifecycle module while keeping existing DesktopPet call sites stable.

Worker Split

  • Lead worker: desktop-shell.
  • Scope kept to desktop startup/shutdown and host-side service process lifecycle.
  • No backend, frontend, Body, Human Ops, settings, staging, commit, cleanup, or revert work was performed.

Files Changed

  • main.py: constructs DesktopServiceLifecycle, exposes compatibility process properties, and delegates service methods.
  • app/service_lifecycle.py: new lifecycle owner for backend launch, ASR launch, warmup progress monitoring, and managed process stopping.
  • tests/test_desktop_service_lifecycle.py: focused split/import/delegation/injection tests.
  • docs/reports/2026-06-20-desktop-service-lifecycle-split.html: this report.

Achieved Effect

  • main.py no longer contains the large backend/ASR service lifecycle method bodies.
  • DesktopPet.ensure_backend_service, ensure_asr_service, request_asr_warmup, warmup monitor helpers, and stop helpers remain as thin compatibility wrappers.
  • backend_process, backend_started_by_app, asr_process, and asr_started_by_app remain readable and writable through DesktopPet properties.
  • The new module receives process, HTTP, clock, threading, path, health-check, Python resolver, and logging helpers by dependency injection, making command construction and local-backend ASR shortcut behavior testable without starting real services.
