macOS 原生审批与目标窗口焦点闭环

Goal

修复全屏应用与批准流程造成的错误桌面截图循环：把批准/拒绝迁移到 macOS 原生弹窗；截图、点击、输入和按键前切换并验证目标应用；动作完成后不再默认置顶 Ipet；仅桌面截图临时隐藏 Ipet。

Worker / subagent split

单 worker 完成，未使用 subagent。Brain 契约负责声明目标应用，Human Ops 负责原生审批与动作安全，Body/桌面主机负责 macOS 焦点和截图策略，前端只展示审批状态，QA 覆盖跨层回归。

Achieved effect

  • 聊天栏不再创建批准/拒绝按钮；待审批 proposal 自动打开 macOS 原生系统弹窗。
  • 批准后保持当前目标应用，不把 Ipet 拉到前台；拒绝或超时不执行动作，并唤回 Ipet 聊天窗口与输入框。
  • click、type_text、key_press 必须携带 target_app。桌面主机先用 Launch Services 激活应用，再读取 macOS 前台进程验证；不匹配时失败关闭。
  • 应用截图同样先切换并验证目标应用，支持其他全屏 Space；截图时不隐藏、不恢复、不置顶 Ipet。
  • 只有明确的桌面截图会临时隐藏 Ipet；截图完成后只恢复可见性，不再调用 raise_()。
  • 后续观察和连续动作继承已验证的目标应用，避免在批准或截图后退回桌面并进入重复观察循环。

测试环境仍报告 PyQt6 与 PySide6 同时加载的 Objective-C 类重复警告；所有测试通过，该警告是现有运行环境问题，不由本轮变更引入。

Remaining work

未在本轮自动打开真实 Chrome/YouTube 或向真实应用输入内容，因为这会改变用户当前应用、焦点和外部会话状态。单元与路由测试已模拟并验证完整顺序。

Recommended next step

在用户明确批准后执行一次真实 macOS 冒烟测试：让 Chrome 进入全屏，触发一次应用截图与一个无副作用的测试点击，分别确认前台应用验证、Ipet 不抢焦点，以及拒绝审批后聊天框能被唤回。
