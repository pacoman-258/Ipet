Desktop Body Payload Bridge Split

Goal

Move DesktopPet.current_body_payload and the tightly related web bridge methods apply_config_to_web, play_motion, play_expression, and play_action out of main.py into an injected Body bridge module while preserving the existing DesktopPet method names as thin wrappers.

Worker / Subagent Split

  • desktop-shell: kept main.py as the Qt host and wrapper owner.
  • body: owns the payload construction and pet presentation web bridge behavior now isolated in app/body_bridge.py.
  • qa-reports: added a focused regression test and this task report.

Files Changed

  • main.py
  • app/body_bridge.py
  • tests/test_desktop_body_payload_bridge.py
  • docs/reports/2026-06-30-desktop-body-payload-bridge-split.html

Achieved Effect

  • Added BodyBridge with injected path, Live2D, QUrl, display-name, vision-normalization, JSON, and JavaScript execution dependencies; the module does not import main.
  • Preserved payload semantics: default model fallback, live2d_model_path refresh, background URL only when enabled and present, chat display/expression/lipsync fields, and normalized vision config.
  • Preserved bridge action semantics: config application script generation, direct motion/expression JavaScript, and reload-model action chaining through applyConfig(...).then(...).
  • Reduced the five DesktopPet methods to thin wrappers so existing call sites and patch points remain available.

Remaining Work

No known follow-up inside this split. A live Qt/WebEngine smoke run can still be useful later because JavaScript execution is only unit-tested through the injected page runner here.

Recommended Next Step

Continue shrinking main.py by extracting one desktop-shell or Body responsibility at a time, with focused tests that import the new module without importing main.
