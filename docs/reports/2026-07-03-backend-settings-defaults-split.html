Backend Settings Defaults Split

Goal

Move the Neo settings default schema out of backend/app.py so the backend app module no longer directly owns the full NEO_DEFAULTS dictionary.

Worker / Subagent Split

Backend worker implemented the file changes. Coordinator/main window remains responsible for review and integration. No other worker files were reverted, cleaned, formatted, staged, or committed.

Files Changed

  • backend/app.py: imports and re-exports settings default constants from the new module.
  • backend/settings_defaults.py: new home for NEO_DEFAULTS, ALLOWED_CONFIG_KEYS, and copy helpers.
  • tests/test_backend_settings_defaults.py: new regression tests for app compatibility exports and default-copy isolation.
  • docs/reports/2026-07-03-backend-settings-defaults-split.html: this report.

Achieved Effect

backend/app.py no longer carries the large defaults dictionary inline. Existing callers can still patch or read backend_app.NEO_DEFAULTS and backend_app.ALLOWED_CONFIG_KEYS, while the schema responsibility now sits in backend/settings_defaults.py.

Remaining Work

No known implementation work remains for this split. Broader settings ownership cleanup is intentionally left to later rounds.

Recommended Next Step

Main/coordinator review should inspect only the settings-defaults split surface and confirm no unrelated app-module changes were introduced by this worker.
