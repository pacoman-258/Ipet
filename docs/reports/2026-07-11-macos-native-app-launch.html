macOS 原生应用启动 Human Ops 能力

Goal

打开应用不再截图寻找 Dock 坐标或模拟点击，改为读取 macOS 应用 bundle 列表并通过 Launch Services 启动，同时保留 Human Ops 批准边界。

Worker / subagent split

单 worker 完成；未使用 subagent。Brain 负责产生或被纠正为 launch_app，Human Ops 负责批准，桌面主机负责应用解析与执行，QA 负责协议和路由回归。

Files changed

  • Brain 与意图：brain/llm.py、backend/computer_use_context.py、backend/react_prompts.py、backend/app_adapters.py
  • Human Ops：human_ops/proposals.py、human_ops/approval_flow.py、human_ops/desktop_actions.py
  • 桌面桥与路由：backend/desktop_command_client.py、app/desktop_action_bridge.py、app/desktop_action_wiring.py、app/desktop_command_wiring.py、app/desktop_command_router.py、main.py
  • 相关测试、docs/WORKFLOW.md 与本报告

Achieved effect

  • 打开应用请求直接形成需要批准的 launch_app proposal，无红点点击预览。
  • 即使模型返回旧式 observe/click，生产适配层也会在纯应用启动意图下改写为 launch_app。
  • 批准后使用 mdfind 读取 application bundle 元数据，匹配精确或唯一应用路径，再用 /usr/bin/open 启动。
  • 应用列表不可用或无唯一匹配时降级为 open -a；整个启动动作不截图、不模拟鼠标，也不需要 Accessibility 事件权限。

Verification

全量回归 702 项全部通过。

  • Brain / Human Ops / proposal 协议覆盖 launch_app 与批准要求。
  • 桌面动作测试验证先读取应用列表，再打开解析后的 bundle 路径。
  • 桌面命令路由测试验证启动应用不会走隐藏窗口与虚拟点击分支。
  • Python 语法检查与 git diff --check 通过。
