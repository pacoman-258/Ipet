Frontend Controller Facade Split

Goal

Move the pure controller compatibility wrappers out of frontend/index.js into a dedicated frontend facade module while preserving runtime behavior.

Worker / Subagent Split

Frontend split worker only. No subagents were used. The main window role remains review-only per user instruction; this worker performed the removal work in its own task scope.

Files Changed

  • frontend/controller_facade.js: new facade module with registry-backed wrapper methods and explicit missing-controller errors.
  • frontend/index.js: creates the mutable controller registry, builds the facade, registers controllers after construction, passes facade methods as dependencies, and starts with facade.init().
  • index.html: loads frontend/controller_facade.js after app bootstrap modules and before frontend/index.js.
  • tests/test_frontend_shell_visuals_source.py, tests/test_frontend_asr_source.py, tests/test_frontend_chat_sidebars_source.py, tests/test_frontend_pet_scene_source.py, tests/test_frontend_app_bootstrap_source.py, tests/test_chat_modes_ui.py: updated source tests for facade ownership and index registry wiring.
  • tests/test_frontend_app_config_source.py, tests/test_frontend_chat_input_state_source.py, tests/test_frontend_chat_messages_source.py, tests/test_frontend_chat_modes_source.py, tests/test_frontend_chat_panel_source.py, tests/test_frontend_chat_stream_source.py, tests/test_frontend_chat_submit_source.py, tests/test_frontend_chat_worklog_source.py, tests/test_frontend_human_ops_preview_source.py, tests/test_frontend_pet_state_notify_source.py, tests/test_frontend_shell_bridge_source.py, tests/test_frontend_speech_source.py, tests/test_index_helpers_source.py: follow-up source-test alignment for legacy wrapper expectations after the facade split.
  • docs/reports/2026-07-07-frontend-controller-facade-split.html: this report.

Achieved Effect

  • frontend/index.js no longer declares the long list of pure forwarding wrappers such as showError, loadTopicHistory, streamChat, loadModel, applyConfig, and init.
  • The new facade reads controllers from a mutable registry at call time, so facade methods can be passed before all controllers exist and still resolve the current controller later.
  • Missing controllers or missing methods now throw explicit IpetControllerFacade errors instead of producing vague undefined-call failures.
  • Source tests now verify the facade module exists, load order is correct, index uses registry/facade wiring, and representative wrappers live in the facade instead of index.
  • Follow-up source tests now assert that old wrapper methods are mapped by frontend/controller_facade.js, that frontend/index.js registers the owning controller and passes facade.method dependencies, and that frontend/index.js no longer declares the removed wrapper functions.

Remaining Work

No known remaining source-test work in this split. Broader runtime/browser smoke testing was not requested and was not run.
