Desktop Active Vision Bridge Split

Date: 2026-07-03

Goal

Move active vision target discovery and capture orchestration provider unwrapping out of main.py into a Qt-free app/active_vision_bridge.py, while preserving the legacy main.py active vision export names for existing tests and callers.

Worker Or Subagent Split

  • desktop-shell: kept main.py as the compatibility surface and converted the two orchestration wrappers to bridge delegates.
  • body: preserved behavior by delegating to existing body.active_vision implementations and the existing screen capture bridge unwrapping helpers.
  • qa-reports: added focused bridge regression coverage and this HTML report.
  • Subagents: none used in this round.

Files Changed

  • app/active_vision_bridge.py: new injected bridge for active vision default-provider identity unwrapping and orchestration delegation.
  • main.py: added _active_vision_bridge() and slimmed discover_active_vision_target_candidates plus capture_active_vision_frame_payload into compatibility wrappers.
  • tests/test_desktop_active_vision_bridge.py: new fake-module tests for import isolation, default-provider unwrapping, custom-provider passthrough, and main.py wrapper delegation.
  • docs/reports/2026-07-03-desktop-active-vision-bridge-split.html: this report.

Achieved Effect

  • app.active_vision_bridge does not import main or Qt bindings at import time.
  • Default main.py discovery providers unwrap to body.active_vision providers before delegation.
  • Default capture and observation providers reuse app.screen_capture_bridge unwrapping, so legacy wrappers do not recurse.
  • Custom injected providers remain custom and are not replaced unless their identity exactly matches the supplied legacy default provider.
  • The existing _active_vision_wrapper alias group and public active vision names in main.py remain in place.

Remaining Work

No known functional follow-up for this slice. The broader working tree already contains many unrelated local changes, so future reviews should continue using focused path and symbol diffs around the active vision bridge surface.

Recommended Next Step

Continue the desktop split by applying the same injected bridge pattern to the next small orchestration surface in main.py, with legacy wrappers retained until all call sites move.
