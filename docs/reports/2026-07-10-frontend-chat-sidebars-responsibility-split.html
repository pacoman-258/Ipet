Frontend Chat Sidebars Responsibility Split

Goal

将话题历史与聊天技能选择从 frontend/chat_sidebars.js 拆为独立叶模块，让组合层只负责模块装配与两个抽屉的互斥协调，同时保留原有公开 API、中文文案和行为契约。

Worker / Subagent Split

实现由本子窗口完成，主窗口负责独立审查、集成验收和全量回归。仓库内其他并行工作者的改动保持原样，未回退、清理或格式化。

Files Changed

  • frontend/chat_topic_history.js：新增，拥有话题状态、加载、创建、选择、删除、消息替换和历史抽屉 DOM 行为。
  • frontend/chat_skills.js：新增，拥有技能目录、默认与选中状态、加载、渲染、切换和技能抽屉 DOM 行为。
  • frontend/chat_sidebars.js：缩减为叶 controller 装配、互斥回调和 API 合并。
  • index.html：在 chat_sidebars.js 前加载两个叶模块。
  • tests/test_frontend_chat_sidebars_source.py：新增职责边界、命名空间、状态归属和脚本顺序断言。
  • tests/test_chat_modes_ui.py：将聚合 source 读取与脚本顺序断言扩展到两个叶模块。
  • docs/reports/2026-07-10-frontend-chat-sidebars-responsibility-split.html：本报告。

Achieved Effect

  • chat_sidebars.js 从 713 行职责混合实现缩减为 22 行组合层。
  • topic 与 skill 两套状态不再共处同一闭包，各叶模块自行拥有 API 与 DOM 行为。
  • window.IpetChatSidebars.createChatSidebarsController 及其合并返回 API 保持不变。
  • 历史和技能抽屉打开时仍会互相关闭，controller graph 无需调整。

Remaining Work

本轮范围内无剩余实现工作。按任务约束未运行全量回归，也未修改 controller graph。

Recommended Next Step

由主窗口在合并并行工作后运行全量回归，并在桌面宿主中手动确认历史抽屉、技能抽屉、新建话题与技能勾选流程。

Verification
