Backend Settings Config Split

Date: 2026-06-15

Goal

Move pure settings/config helper logic out of backend/app.py into backend/settings_config.py while keeping the existing app helper names as thin wrappers.

Worker Split

This round was handled by the backend settings/config split worker. Main window, frontend files, and settings UI files were left untouched.

Files Changed

  • backend/app.py - kept settings/config helper names and delegated pure logic to the new module.
  • backend/settings_config.py - added pure config loading, normalization, redaction, payload, merge, and save helpers.

  • docs/reports/2026-06-15-backend-settings-config-split.html - this report.

Achieved Effect

The settings/config logic now has a dedicated module that does not import backend.app. The app wrapper functions still use the current CONFIG_PATH, NEO_DEFAULTS, and ALLOWED_CONFIG_KEYS at call time, preserving existing tests and monkeypatch behavior.

The existing API key preview, redaction, clear handling, utf-8-sig reads, and JSON save format with two-space indentation plus trailing newline were preserved.
