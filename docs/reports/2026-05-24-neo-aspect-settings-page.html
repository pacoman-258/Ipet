Neo Aspect 设置页重构报告

本报告记录 2026-05-24 这一轮任务对 Ipet 设置页和 Qt 设置入口的改造结果。

分支：Neo_Aspect 范围：Web 设置页 / Qt 设置窗口 / UI 契约测试 状态：已完成并通过目标验证

本轮修改了哪些方面

  • 将 settings.html 重做为 Neo Aspect 设置页，保留原有桌面窗口视觉风格，但内容改为 Body、Brain、Human Ops、Memory、Skills、Diagnostics。
  • 将 settings.js 从旧运行时管理脚本改为 Ipet 本体配置脚本，支持静态预览、表单加载保存、诊断卡片、审阅队列和点击红点预览。
  • 在 settings.css 中补充红点点击预览与审阅列表样式，并调整红点默认位置，避免被 Dock 遮挡。
  • 修改 main.py 的设置页入口：Qt 宿主现在复用单个设置窗口，重复点击只聚焦或显示已有窗口，不再不断打开新页面。
  • 新增 Neo Aspect 设置页测试，并把旧设置页 UI 测试改为确认已舍弃的 Hermes、AstrBot、MCP、runtime 管理控件不再出现。
  • 更新架构设计文档和执行计划，记录设置页进入 Neo Aspect 内容模型，以及设置窗口单例行为。

达成了什么效果

  • 设置页现在表达的是新的 Ipet：有身体、有大脑、有人类式电脑操作、有记忆和技能沉淀。
  • Human Ops 的 act 审批逻辑在 UI 上可见，点击类动作通过红点和说明文字变成可审阅对象。
  • 旧 agent runtime 生态不再占据设置页，不继续把 Ipet 伪装成运行时管理平台。
  • 用户重复从 Qt 窗口打开设置页时，体验变成召回已有窗口，减少重复页面和状态混乱。
  • 静态预览模式可在没有后端 API 时打开页面，便于视觉检查和快速设计迭代。

已验证内容

  • 通过浏览器视觉检查：总览、Body、Human Ops 面板可切换，红点预览显示在可见区域内。
  • 通过单元测试：tests.test_neo_aspect_settings_page、tests.test_neo_aspect_core、tests.test_main_runtime_env。
  • 通过编译检查：py_compile app/settings_schema.py main.py。
  • 通过空白检查：目标文件 git diff --check 无尾随空白问题。

待办事项还有哪些

  • 后端仍保留大量旧 runtime、MCP、Hermes、AstrBot 代码和 API，下一阶段应按模块直接删除或迁移。
  • 根目录 UI 文件暂时还在过渡位置，最终应进入清晰的 frontend / body 边界。
  • Brain 目前已有决策数据结构，但真实 LLM 决策循环和单步执行状态机还需要落地。
  • Human Ops 需要从 preview / approval 数据结构走向真实 observe、click、type、hotkey、wait、verify 执行器。
  • Memory & Skills 还需要真实审阅队列、持久化、编辑、批准、拒绝和合并流程。

推荐的下一步

  • 优先做破坏性后端瘦身：删除 agent runtime、MCP 管理、Hermes/AstrBot 平台化配置入口，只保留能映射到 Body、Brain、Human Ops、Memory & Skills 的能力。
  • 把 Brain 单步循环打通：输入用户目标和观察结果，输出唯一下一步 say / observe / propose_act / propose_remember / propose_learn_skill。
  • 先实现 Human Ops 的最小闭环：观察屏幕、生成点击预览、人工批准、执行点击、再次观察。
  • 为每轮任务继续生成 HTML 报告，形成 Ipet 重构过程的可审阅沉淀。
