Ipet 全局提示词与人格文件选择

日期：2026-07-13

目标

借鉴 Hermes 的提示词分层，将 Ipet 的长期能力边界、证据纪律、思考方式、Human Ops 安全合同和 JSON 输出 schema 统一迁入 prompts/Ipet.md；用户自定义 Markdown 只负责人格、角色扮演和说话风格，并可在 Brain 页面选择、停用、查看文件名与内容预览。

研究依据

  • Hermes Prompt Assembly：稳定系统提示词与临时叠加层分离，并明确装配顺序。
  • Hermes Personality / SOUL.md：人格文件聚焦身份、语气和沟通风格。
  • Hermes API System Prompt Handling：外部自定义叠加在核心提示词上，不移除工具与核心能力。
  • Hermes Structured Outputs：用明确 schema 约束仅输出 JSON 对象。

Worker / Subagent 分工

本轮由主代理单人完成；未启动 subagent。Brain 提示词、设置契约、前端控件、测试与报告按同一变更链集成，避免并行修改高冲突入口。

文件变更

  • 全局提示词：prompts/Ipet.md、brain/llm.py
  • 配置与后端：app/default_config.py、backend/settings_defaults.py、backend/settings_routes.py、backend/app_route_dependencies.py、backend/app_route_context.py、backend/app.py
  • Brain 设置页：settings.html、settings.css、settings.js、settings_form.js
  • 文档：docs/architecture.md、docs/WORKFLOW.md
  • 测试：tests/test_brain_structured_replies.py、tests/test_backend_settings_routes.py、tests/test_neo_aspect_settings_page.py、tests/test_desktop_default_config.py、tests/test_settings_form_source.py

已达成效果

  • Ipet.md 成为所有 provider 共用的唯一全局能力合同，并由受控模板一次性渲染人格、自我状态和会话摘要。
  • 选中的人格文件优先于旧 inline persona；旧配置仅在未选择文件时作为兼容回退。
  • 人格内容不能扩大动作范围、绕过审批、削弱验证或覆盖 JSON schema；全局边界在动态内容后再次重申。
  • 只读接口仅枚举 prompts/ 直属的 UTF-8 .md，排除 Ipet.md，限制单文件 100,000 字符及最多 100 份人格，并阻断路径逃逸与外部 symlink。
  • Brain 页面显示选择按钮、停用按钮、当前文件名、目录下拉项和只读内容预览；配置只保存 brain.persona_prompt_file。
  • 删除或损坏已选文件时不静默换人格：设置页显示缺失，Brain 调用明确失败。

剩余工作

没有阻塞项。仓库当前已有的 prompts/muramasa_system_prompt.json 仍是旧 JSON 资产，不会出现在 Markdown 人格选择器中；本轮没有复制、改写或删除该用户资产。

推荐下一步

用户可把自定义人格保存为 UTF-8 .md 并放入 prompts/，重新载入 Brain 设置后选择并保存。若未来需要导入外部文件，应另行设计带文件写入审批、同名冲突处理和内容扫描的导入流程，而不是扩大当前只读接口。
