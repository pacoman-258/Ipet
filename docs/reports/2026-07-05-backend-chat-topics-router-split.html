Backend Chat Topics Router Split

Status: DONE

Goal

Move the /api/skills and /api/chat/topics FastAPI route decorators out of backend/app.py into backend/chat_topics_routes.py while preserving the existing HTTP paths, methods, status codes, response shapes, and monkeypatch-friendly helper delegation.

Worker / Subagent Split

Backend subwindow owned the implementation, tests, and report for this route split. The main window is expected to review the result only. No frontend, desktop host, settings, ASR, TTS, audio, or unrelated worker report files were intentionally changed.

Files Changed

  • backend/app.py: keeps _chat_topics_route_deps() and registers the split chat topics router.
  • backend/chat_topics_routes.py: owns the skills and chat topics route decorators through create_chat_topics_router() and register_chat_topics_routes().
  • tests/test_backend_chat_topics_routes.py: asserts app-level delegation, app source split constraints, and split-module route decorator ownership.
  • docs/reports/2026-07-05-backend-chat-topics-router-split.html: records this task round.

Achieved Effect

  • backend/app.py no longer contains inline decorators for /api/skills or chat topic routes.
  • backend/chat_topics_routes.py now exposes a route factory and registration helper matching the settings route split pattern.
  • Route handlers remain in the split module and call the existing helper functions.
  • Dependencies resolve the current TOPIC_STORE at request time, preserving tests and callers that patch backend_app.TOPIC_STORE.
  • ASR, TTS, audio, settings, frontend, and desktop route code were left outside this task.

Remaining Work

None for this split. Broader backend route decomposition can continue in separate worker-owned tasks.

Recommended Next Step

Main window review should confirm the split scope and then proceed with the next backend route extraction only if assigned to a separate worker.
