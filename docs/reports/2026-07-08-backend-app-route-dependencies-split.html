Backend App Route Dependencies Split

Goal

Move the route dependency factory assembly out of backend/app.py into a dedicated module, while keeping the legacy private factory names as thin forwarding wrappers and preserving route behavior.

Worker Split

  • Subwindow: implemented the backend refactor and test coverage.
  • Main window: review-only acceptance path; no patching.

Files Changed

  • backend/app.py
  • backend/app_route_dependencies.py
  • tests/test_backend_app_route_dependencies.py

Achieved Effect

  • Route dependency assembly now lives in backend/app_route_dependencies.py.
  • Legacy private factory names in backend/app.py remain available as thin forwarders.
  • Settings route dependencies still call the existing backend wrapper patch points.
  • Chat stream, human ops decision, brain models, audio, health, and chat topics dependencies continue to resolve through the current backend wiring.
  • No @app.get, @app.post, @app.websocket, or @app.delete decorators were reintroduced into backend/app.py.

Remaining Work

None for this split. The route dependency wiring is now isolated in the new module, and the backend compatibility export for DEFAULT_TOPIC_TITLE has been restored after the main-window regression report.

Recommended Next Step

Use the same pattern for any remaining backend wiring that still lives directly in backend/app.py, but only if a future task explicitly targets it.
