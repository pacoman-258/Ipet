Backend App Adapters Split

Status: DONE

Goal

Continue shrinking backend/app.py by moving the remaining Human Ops observe, observe prompt/result, ReAct prompt, and computer-use compatibility adapters into a dedicated backend adapter module while preserving the old private names exported by backend.app.

Worker / Subagent Split

  • Implementation worker: this backend app adapter split window.
  • Main window: expected to verify and accept, with no implementation edits required.
  • Other agents: existing unrelated worktree changes were left untouched.

Files Changed

  • backend/app_adapters.py - new aggregation adapter for app-level private compatibility names.
  • backend/app.py - imports and re-exports adapter names instead of defining local implementation bodies.
  • tests/test_backend_app_adapters.py - new regression coverage for adapter re-exports and representative paths.
  • tests/test_backend_observe_result.py - updated the app boundary assertion to expect adapter re-export instead of an app-local thin wrapper.
  • docs/reports/2026-07-08-backend-app-adapters-split.html - this report.

Achieved Effect

  • backend/app.py current size was reduced from 687 lines observed before this task to 432 lines after the split.
  • Computer-use intent helpers, structured context helpers, ReAct helper wrappers, observe prompt/result helpers, and Human Ops observe composition now live in backend/app_adapters.py.
  • backend.app still exposes the legacy private names used by existing contract tests.
  • The Human Ops observe adapter lazily resolves backend.app._send_desktop_command and backend.app.VisionAnalyzer, preserving old patch points used by tests.
  • No @app.get, @app.post, @app.websocket, or @app.delete route decorators were introduced in backend/app.py.

Remaining Work

  • backend/app.py still owns proposal-flow dependency assembly and other route dependency factories.
  • Future rounds can move Human Ops proposal-flow compatibility wrappers into a similar adapter once the app globals are isolated behind a small state dependency object.

Recommended Next Step

Split the remaining Human Ops proposal-flow compatibility functions and route dependency factories only after the current adapter boundary is accepted.
