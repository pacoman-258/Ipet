Neo Brain SOCKS 代理报错修复报告

本轮修复模型列表拉取时因为系统 SOCKS 代理环境变量触发 socksio 缺失而失败的问题。

状态

DONE

Brain provider HTTP 客户端现在默认不继承进程环境代理，因此不会因为 ALL_PROXY、HTTP_PROXY 或 HTTPS_PROXY 指向 SOCKS 代理而要求安装 socksio。

根因

新增的模型发现功能改由后端用 httpx.AsyncClient 请求 provider。httpx 默认会读取环境代理；如果环境代理是 SOCKS，但项目没有安装 httpx[socks]，请求会在真正连接前失败。

已改内容

  • brain/llm.py：创建 Brain provider HTTP client 时设置 trust_env=False。
  • tests/test_brain_llm_providers.py：新增回归测试，断言 Brain HTTP client 默认忽略环境代理。

达成效果

  • 模型列表拉取不会再因为缺少 socksio 直接显示 provider 失败。
  • 实际 Brain 聊天调用也复用同一客户端边界，因此同样避开这个环境代理问题。
  • 不新增依赖，不改变用户填写的 endpoint/key/model 配置。
