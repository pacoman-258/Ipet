Frontend App Bootstrap Split

DONE

Goal

Move application startup/bootstrap responsibilities out of frontend/index.js into a dedicated bootstrap module so the entry file no longer directly owns PIXI initialization, QWebChannel wiring, DOM event listener binding, pending config handling, or the public window.PET_APP API object.

Worker / Subagent Split

  • Frontend worker: implemented the source split, script ordering, and focused source tests.
  • Main/coordinator window: reviewed integration and found legacy source tests still expected relocated listener wiring in frontend/index.js.
  • QA/test-alignment worker: aligned the test expectations to the new ownership boundary without changing production code.
  • QA/test-alignment worker on 2026-07-05: moved the chat panel interaction-install assertion from frontend/index.js to frontend/app_bootstrap.js.
  • No staging, commit, dependency install, network access, or destructive cleanup was performed.

Files Changed

  • frontend/app_bootstrap.js: added bootstrap controller and public API installer.
  • frontend/index.js: added dependency collection for bootstrap controller and reduced init to a thin delegate.
  • index.html: loads frontend/app_bootstrap.js after app config and before app entry.
  • tests/test_frontend_app_bootstrap_source.py: added source regression coverage for this split.
  • tests/test_frontend_app_config_source.py: synchronized script-order assertions with the new bootstrap script.
  • tests/test_chat_modes_ui.py: updated chat/memory mode source assertions so frontend/index.js keeps the thin wrapper and payload checks while frontend/app_bootstrap.js owns the memory mode button listener check.
  • tests/test_frontend_chat_panel_source.py: keeps chat panel behavior assertions in frontend/chat_panel.js, confirms frontend/index.js only creates the controller and thin wrappers, and reads frontend/app_bootstrap.js for the relocated interaction-install call.
  • docs/reports/2026-07-03-frontend-app-bootstrap-split.html: this report.

Achieved Effect

  • window.IpetAppBootstrap.createAppBootstrapController(deps) now owns renderer setup, Qt bridge setup, UI event wiring, pending config consumption, startup error handling, and window.PET_APP.
  • frontend/index.js no longer contains direct new window.PIXI.Application, new window.QWebChannel, window.PET_APP = { ... }, pending config storage, or large direct listener wiring.
  • Existing app config, pet scene, and shell bridge controller delegation patterns remain intact.
  • The chat modes UI test now verifies HTML button datasets, index-level button collection, chatModesController creation, setMemoryMode wrapper delegation, memory_mode payload semantics, and the relocated memory listener in frontend/app_bootstrap.js.
  • The chat panel source test now verifies frontend/app_bootstrap.js receives deps.chatPanelController and invokes chatPanelController.installChatPanelInteractions() inside installEventListeners().
