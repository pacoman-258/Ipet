Local-first desktop agent shell

Ipet 桌面宠物 Agent 外壳

Ipet 把桌宠宿主、聊天 UI、FastAPI 后端、TTS/ASR、设置页、审批交互和可选屏幕视觉证据治理整合在一起。AstrBot 是默认 Runtime，负责 Agent 决策、会话、插件、MCP、知识库、Provider 与 QQ/NapCatQQ 集成；Hermes 是可手动选择的次选/高级 Runtime。Ipet 负责桌面体验和运行时适配。

项目定位

桌面外壳

Qt / WebEngine 悬浮桌宠窗口、设置页、窗口行为、角色资源、TTS 与 ASR 都由 Ipet 管理。

可插拔运行时

默认使用 runtime.active=astrbot；Hermes 通过手动切换接入，聊天流统一整理成稳定的前端 SSE 事件。

证据优先

屏幕视觉默认关闭；启用后也只注入受控文本证据，不把原始截图写入仓库或状态接口。

路径 职责

根目录只放启动入口、核心 UI、配置示例和 README。一次性输出、热搜报告、缓存、运行状态文件和个人配置不要进入版本库。

快速开始

1. 检查 Python

.\.venv\Scripts\python.exe -V

2. 创建本地配置

Copy-Item pet_config.example.json pet_config.json

3. 修改配置

在 pet_config.json 中设置模型路径、AstrBot 地址、API Key、sidecar 命令，以及可选 TTS、ASR、视觉参数。默认使用 runtime.active=astrbot；如需 Hermes，手动改为 runtime.active=hermes 并配置 runtime.adapters.hermes。

4. 启动桌宠

uv run --no-sync python main.py

运行时工作流

main.py 启动桌面宿主和 FastAPI 后端；前端向 /api/chat/stream 发送聊天请求；后端解析 active runtime，必要时先执行 Ipet 自有视觉证据门，默认调用 AstrBot 适配器，或在手动选择 Hermes 时调用 Hermes 适配器。

桌面宿主启动 Qt 窗口、后端与可选 sidecar。
前端 UI发送聊天请求并渲染 SSE。
后端代理默认选择 AstrBot；Hermes 为手动次选。
视觉证据按需注入受控上下文。
运行时负责推理、工具、会话与最终回答。

active runtime 不可用时，聊天流返回明确错误；后端不会悄悄回退到旧本地 Agent runtime，也不在 AstrBot 与 Hermes 之间自动故障回退。

自动视觉

自动视觉默认关闭，由 vision.* 配置控制。Ipet 负责截图、状态、分析器路由和证据治理；原始截图不落盘，设置与状态接口不暴露图片数据。

  • 被动链路：保留短屏幕变化时间线，用作背景上下文。
  • 主动链路：视觉问题或强制 grounding 时执行实时观察，只允许轻交互。
  • Analyzer v2：显式启用后可接入本地 OCR 或 OpenAI-compatible/local VLM。
  • 失败处理：分析失败只形成 bounded unknowns，不伪造 observations。

配置与仓库卫生

  • pet_config.json 只保留在本地，不提交。
  • .pet_runtime_*、backend/audio_cache/、data/chat_topics/、fileplay/、node_modules/、.venv/ 和缓存目录保持忽略。
  • model/ 中已有示例/参考模型资源；私人、大体积、下载或生成模型在提交前应确认已忽略。
  • API Key、本地绝对路径、截图 payload、生成音频、下载的 MCP 运行时和临时分析输出不进入版本库。

测试

完整测试命令：

python -m unittest discover -s tests -p "test*.py" -v

更小的回归切片见 AGENTS.md；自动视觉相关切片是：

python -m unittest tests.test_active_vision tests.test_vision_analyzer tests.test_vision_api tests.test_vision_service tests.test_vision_state tests.test_health_endpoint -v
